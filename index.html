Bloque 1 · Conceptos básicos

Programa, proceso, servicio e hilo

Los cuatro conceptos sobre los que se construye todo el módulo. Si entiendes la analogía de la cocina, tienes medio tema hecho.

Teoría La cocina

Receta= programa: instrucciones guardadas en disco. No hace nada sola.
Cocinero= CPU (un núcleo): sigue los pasos uno a uno.
Ingredientes= datos de entrada del programa.
Cocinando= proceso: la receta en marcha, con su PID y su memoria.
La misma receta cocinada dos veces son dos procesos: dos ventanas del navegador tienen dos PID distintos.

Proceso en memoria

Un proceso es un programa en ejecución: el código más todo lo necesario para ejecutarlo. Tiene un PID, su propia memoria (código, datos, heap, pila), ficheros y sockets abiertos, registros de CPU y al menos un hilo.

El PCB: la ficha de cada proceso

El sistema operativo guarda la información de cada proceso en su PCB (Process Control Block). Al cambiar de proceso, guarda y carga estos datos:

CampoPara qué sirve
PID y PPIDquién es y quién lo creó
Estadonuevo, listo, ejecución, bloqueado, terminado
Contador de programasiguiente instrucción a ejecutar
Registros de CPUpara reanudarlo donde lo dejó
Memoriadónde están código, datos, heap y pila
Ficheros y socketsrecursos abiertos
Usuario y permisoscontexto de seguridad
Prioridaddatos para el planificador

PID, PPID y jerarquía

Todo proceso tiene un PID y guarda el PPID (el PID de su padre). Todos descienden del proceso 1 (systemd o init en Linux). Desde Java:

ProcessHandle yo = ProcessHandle.current();
System.out.println("Mi PID: " + yo.pid());
yo.parent().ifPresent(p ->
    System.out.println("Mi PPID: " + p.pid()));

Zombis y huérfanos

Zombi · ya terminóSu padre no ha recogido el código de salida con wait(). No usa CPU pero ocupa un PID. En ps sale con Z o <defunct>.
Huérfano · sigue vivoSu padre terminó antes. Lo adopta init/systemd (PID 1), que recogerá su salida.
Un proceso bloqueado para siempre esperando un dato que nunca llega no es un zombi: sigue vivo. Es un error de programación.

Servicios (demonios)

Un servicio es un proceso no interactivo que el sistema arranca y controla sin intervención del usuario: sin ventana, suele arrancar con el sistema y da servicio a otros (impresión, red, bases de datos, servidores web).

# Windows
Get-Service | Where-Object Status -eq Running
# Linux (systemd)
systemctl list-units --type=service
systemctl status ssh

Hilos

Un hilo es un flujo de ejecución dentro de un proceso. Los hilos de un proceso comparten memoria y recursos; cada uno tiene su propia pila y su contador de programa. Solo se ejecutan a la vez si hay varios núcleos.

ProcesoHilo
Memoriapropia y aisladacompartida
Crearcostosobarato
ComunicarIPC (tuberías, sockets)variables compartidas
Si fallacae él solocae todo el proceso

# Linux / WSL

Bloque 2 · Tipos de programación

Concurrente, paralela y distribuida

Tres formas de hacer varias cosas a la vez, según haya uno o varios núcleos, o varios ordenadores.

Teoría Un cocinero o dos

Concurrencia · 1 cocineroPica la ensalada, para a remover la sopa y vuelve a picar. Los dos platos avanzan, pero nunca en el mismo instante.
Paralelismo · 2 cocinerosCada uno hace un plato. Avanzan a la vez de verdad: hacen falta dos núcleos.
La concurrencia es organizar varias tareas; el paralelismo es tener más manos para hacerlas a la vez.
TérminoSignificado
Concurrenciavarias tareas en curso a la vez; con un núcleo, el SO las alterna cada pocos milisegundos (multiprogramación).
Paralelismovarias tareas ejecutándose en el mismo instante en núcleos distintos (multiprocesamiento).
Multitareacapacidad del SO de mantener varias tareas en curso, con uno o con varios núcleos.

Programación distribuida

Varios ordenadores independientes, conectados por red, colaboran como si fueran un solo sistema. No comparten memoria: se comunican con mensajes.

EjemploQué reparte
Clústercálculo entre nodos de un centro de datos
Cloud (AWS, Azure, GCP)servidores y almacenamiento bajo demanda
Microserviciosuna aplicación en muchos servicios pequeños
Supercomputadorsimulación, meteorología, IA
VentajasEscala añadiendo máquinas y tolera fallos: si cae un nodo, siguen los demás.
InconvenientesLa red falla y tarda; sincronizar es difícil y hay que proteger los datos que viajan.

Bloque 3 · Estados de un proceso

Cinco estados y seis transiciones

El ciclo de vida de un proceso, desde que se crea hasta que termina, y quién decide cada cambio.

Teoría El diagrama

  • Solo hay un proceso en ejecución por núcleo.
  • Los listos esperan CPU; los bloqueados esperan un suceso (disco, red, teclado).
  • Un bloqueado nunca pasa directo a ejecución: vuelve a Listo y espera turno.
  • Solo se bloquea quien se está ejecutando (Listo → Bloqueado es imposible).
  • Un terminado no revive: habría que crear otro proceso.

Bloque 4 · Planificación de la CPU

Quién usa cada núcleo, y cuándo

El planificador decide qué proceso pasa a ejecución. Aquí está la parte de cálculo del tema: diagramas de Gantt, tiempos de espera y de retorno.

Teoría Planificadores y políticas

A largo plazoDecide qué procesos nuevos entran en la cola de listos. Se ejecuta poco; casi no existe en ordenadores personales.
A corto plazoElige qué proceso de la cola de listos pasa a ejecución. Actúa cada pocos milisegundos: debe ser muy rápido.
PolíticaCuándo cambia de proceso
Cooperativasolo si el proceso se bloquea o termina (sin expropiación)
Apropiativaexpulsa al proceso si llega uno más prioritario
Tiempo compartidocada proceso tiene un quantum; al agotarlo, cede la CPU

Algoritmos

AlgoritmoCómo eligeRiesgo
FCFS (FIFO)por orden de llegadalos cortos esperan detrás de los largos
SJFel que necesita menos CPUinanición de los largos
Prioridadesel de mayor prioridadinanición de los de baja prioridad
Round Robinturnos de un quantum, en círculoquantum mal elegido
Colas multinivelvarias colas con distinto algoritmocomplejidad
Inanición: un proceso listo que nunca llega a ejecutarse. Se evita con envejecimiento (aging): la prioridad sube con el tiempo de espera.

Fórmulas que tienes que saber

Retornofin − llegada
Esperaretorno − ráfaga
Mediasuma ÷ nº de procesos

En Round Robin con llegadas, el orden de la cola manda: un proceso que llega durante un quantum se pone en la cola antes que el proceso que acaba de agotar su quantum.

El cambio de contexto

Al cambiar de proceso, el SO guarda el estado del saliente en su PCB y restaura el del entrante. Es tiempo en que la CPU no hace trabajo útil: por eso un quantum demasiado pequeño es mala idea.

Bloque 5 · Procesos en Java

ProcessBuilder configura, Process controla

Lo que haces en la terminal con java HolaMundo, ahora lo hará tu programa. Todo con JDK 21 o superior.

Teoría Las dos clases

ProcessBuilderConfigura el proceso antes de lanzarlo: command(), directory(), environment(), redirecciones. Lo lanza con start().
ProcessEl proceso hijo ya en marcha: pid(), waitFor(), exitValue(), destroy(), flujos de entrada y salida.
Ojo: start() es de ProcessBuilder, no de Process. Runtime.exec(String) está obsoleto desde Java 18. Si el ejecutable no existe o no tiene permisos, start() lanza IOException.

Lanzar y esperar

ProcessBuilder pb = new ProcessBuilder("ping", "-c", "3", "8.8.8.8"); // Windows: "-n"
pb.directory(new File(System.getProperty("user.home"))); // carpeta de trabajo
pb.environment().put("MODO", "prueba");  // variable de entorno
pb.inheritIO();                           // el hijo escribe en nuestra consola
Process p = pb.start();                   // puede lanzar IOException
System.out.println("PID del hijo: " + p.pid());
int codigo = p.waitFor();                // bloquea hasta que termina (0 = bien)
Excepción / reglaQué significa
IOExceptionstart() no pudo crear el proceso: no existe o sin permisos
InterruptedExceptionalguien interrumpió al padre mientras esperaba en waitFor(). Restablece con Thread.currentThread().interrupt()
Comando troceadoel programa y cada argumento por separado. Nunca "ping -c 3 8.8.8.8" en una sola cadena

Padre e hijo: argumentos de ida, código de salida de vuelta

El padre pasa datos al hijo como argumentos (llegan como texto en args, hay que convertirlos). El hijo responde con System.exit(n), y el padre recibe n como valor de waitFor().

Abrir una web según el sistema

SistemaComando para ProcessBuilder
macOS"open", url
Linux"xdg-open", url
Windows"cmd", "/c", "start", "", url

En Windows, start es una orden interna de cmd. El "" vacío es el título de la ventana: sin él, start toma la URL como título. El navegador que se abre no es hijo nuestro: nuestro hijo es open/cmd, que termina enseguida con código 0.

Bloque 6 · Comunicar y controlar

Hablar con el hijo, esperarlo y terminarlo

Leer lo que escribe el hijo, enviarle datos, encadenar procesos, observarlos y matarlos.

Teoría Tres flujos vistos desde el padre

Flujo del hijoEl padre lo usa conDirección
stdin (entrada)getOutputStream() / outputWriter()padre → hijo
stdout (salida)getInputStream() / inputReader()hijo → padre
stderr (errores)getErrorStream() / errorReader()hijo → padre
Truco para el examen: getInputStream() lee la salida del hijo. Los nombres están desde el punto de vista del padre: lo que para el padre es una entrada, para el hijo es su salida.

Por defecto los flujos van a tuberías (PIPE). Si el padre no las lee y el hijo escribe mucho, el búfer se llena y el hijo se bloquea. Por eso: lee primero, waitFor() después.

Leer la salida línea a línea

ProcessBuilder pb = new ProcessBuilder("java", "-version");
pb.redirectErrorStream(true);   // stderr se mezcla con stdout
Process p = pb.start();
try (BufferedReader br = p.inputReader(StandardCharsets.UTF_8)) {
    String linea;
    while ((linea = br.readLine()) != null) {  // null = el hijo cerró
        System.out.println("[hijo] " + linea);
    }
}
System.out.println("Código: " + p.waitFor());  // DESPUÉS de leer

java -version escribe en stderr: sin redirectErrorStream(true) no leerías nada por getInputStream().

Redirigir en lugar de leer

MétodoEfecto
inheritIO()los tres flujos a la consola del padre
redirectOutput(File)la salida a un fichero (lo sobrescribe)
Redirect.appendTo(f)la salida al final de un fichero
redirectInput(File)la entrada se lee de un fichero
redirectError(...)los errores a otro destino
Redirect.DISCARDdescarta la salida (Java 9+)

Enviar datos al hijo

Process p = new ProcessBuilder("sort").start();
try (BufferedWriter w = p.outputWriter()) {
    w.write("pera\nmanzana\nkiwi\n");
}   // cerrar = fin de datos para el hijo
System.out.print(new String(p.getInputStream().readAllBytes()));

Hay que cerrar el flujo: si no, el hijo sigue esperando datos y no termina nunca.

Esperar con límite y terminar

MétodoQué hace
waitFor(t, unidad)espera como mucho ese tiempo; true si terminó
isAlive()true si el hijo sigue en marcha
destroy()pide terminar (SIGTERM): puede cerrar ordenadamente
destroyForcibly()lo mata sin avisar (SIGKILL)
exitValue()código de salida; excepción si aún no terminó
onExit()CompletableFuture que se completa al terminar

ProcessHandle: el Administrador de tareas desde Java

ProcessHandle.allProcesses()
    .filter(ph -> ph.info().command().isPresent())
    .limit(10)
    .forEach(ph -> System.out.println(ph.pid() + " " + ph.info().command().get()));

info() da orden, argumentos, usuario, hora de inicio y tiempo de CPU. children() y descendants() recorren el árbol (Java 9+).

Encadenar procesos: startPipeline

// Equivale a: ps -e | grep java | wc -l
List<Process> tuberia = ProcessBuilder.startPipeline(List.of(
    new ProcessBuilder("ps", "-e"),
    new ProcessBuilder("grep", "java"),
    new ProcessBuilder("wc", "-l")));
Process ultimo = tuberia.get(tuberia.size() - 1);
